# 本地导入与元数据复用

本页维护服务端数据契约与跨端历史记录；iOS 界面与测试在 [ReadDeck App](https://github.com/everlst/ReadDeck/blob/main/docs/local-import-metadata.md) 维护。

## 书库与栏目

顶部横向栏目条包含全部栏目、漫画、小说、其他，以及当前服务器栏目和设备上的自建栏目。“全部”筛选菜单切换全部、已下载、本地导入，三种范围均支持列表和卡片显示。

“全部”同时显示服务器作品与本地导入；已有服务器作品的下载副本不会重复显示为另一张卡片。已下载筛选按本地卷册显示。自建栏目保存在设备上；选用服务器自定义栏目时保留其设备侧定义，并以服务器实例区分同名/同 ID 栏目。

导入前可指定栏目、新建栏目、补充书名与作者，并选择刮削服务器。默认不开启刮削。EPUB 会读取内嵌标题和作者；未指定栏目时按格式归类。书籍菜单提供信息编辑、移动栏目和重新请求元数据，刮削不会覆盖手动选择的栏目。

## 文件边界

原文件复制进 App 沙盒，本地资源的 `profileID` 保持为空。刮削服务器关联单独记录，不会把本地导入变为服务器下载，也不会将本地阅读进度同步到该服务器。退出服务器登录会暂停关联的未完成刮削任务，本地文件和已保存元数据继续保留。

客户端只通过 JSON 发送四个字段：

```json
{
  "title": "作品名称",
  "author": "作者",
  "originalName": "作品名称 Vol.01.epub",
  "mediaType": "novel"
}
```

不发送文件路径、文件字节、图片、正文或封面。`mediaType` 为 `comic` 或 `novel`；已指定漫画/小说栏目时采用该类型，否则按文件格式推断。封面优先保留本机已有图片，缺少时可将刮削结果的封面下载到设备。

服务端接口拒绝额外字段、过长文本、路径形式的文件名和非 JSON 请求。本地描述只生成元数据记录，不写入书库资源索引，也不创建可下载的服务端书籍。

## 接口与任务

- `POST /api/local-metadata`：创建或复用描述刮削任务；未完成返回 202，已完成返回 200。
- `GET /api/local-metadata/:id`：查询当前账号自己的任务。其他账号的任务返回 404。
- 状态为 `queued`、`running`、`success` 或 `failed`。成功结果包括作品/卷册 ID、书名、作者、简介、封面 URL 和复用标记。

读者无需服务器书库来源权限也能刮削自己的本地书籍。任务要求有效登录，账号停用或需要修改初始密码时不能继续。任务以权限 `600` 保存到 `data/metadata/local-requests`，先落盘再报告完成；服务重启后恢复未完成任务。客户端保留任务 ID，支持切回 App 后继续查询及手动重试。

## 复用策略

开启「AI 联网刮削」时，四字段描述直接进入完整联网流程，不预先运行旧的名称解析、候选匹配及翻译链。结果支持无 Bangumi ID 的作品，增加 metadataKey、detailKey、sourceUrl 及来源信息，原有数字 ID 字段仍为数字或 null。

设备任务按刮削模式、策略版本与完整描述指纹复用；模式或描述变化不会复用旧任务。回退中文化结果也记录完成状态及原因，避免相同资料反复联网。执行开始时固定 AI 配置，排队期间不持久化密钥。完整规则见[元数据刮削](metadata-scraping.md)。

设备新增卷册的原始 title、明确提供的非空 author 和 mediaType 完全一致时，可沿用此前已确认的主作品及译名，仅处理新文件名对应的资源。作者缺失、作者或类型不同则完整识别，不按名称相似度合并。强制重刮始终跳过该上下文。

下述按书名及 Bangumi ID 的共享复用适用于关闭联网刮削时的传统流程。

共享结果保存在 `data/metadata/shared-scrapes`。优先检查已知书名、别名、作者与作品类型，再决定是否调用外部匹配；确定作品 ID 后，对该作品的抓取使用串行保护，后到的请求可直接读取前一个请求的结果。

同作品的已知卷号会映射到已刮削的卷册条目，复用简介、封面和翻译。新增或无法可靠定位的卷册仍走匹配流程。ZIP/CBZ、高清版/电子版等来源差异不会单独触发同一卷册的完整重刮；实际来源文件和版本信息保留，由现有作品聚合层合并展示。

名称冲突或作者不符时不直接复用；小说和漫画按不同作品类型处理。这里合并的是识别任务与元数据，不删除原文件。

## 验证

```sh
npm run test:local-metadata
```

测试覆盖并发请求复用、作品/卷册零外部调用复用、来源版本聚合、同名异作者/改编区分、任务账号隔离、重启恢复，以及拒绝资源上传。真实 iPhone 流程和调试产物说明见[真机调试](https://github.com/everlst/ReadDeck/blob/main/docs/device-debugging.md)。

设备手动重刮通过 `POST /api/local-metadata?force=true` 跳过已完成任务及共享结果；JSON 仍只发送四字段。相同强制请求在排队或执行期间合并，普通请求与强制请求分开，成功后普通查询复用最新完成结果。
