# 服务器设置与元数据服务

初始管理员可以创建管理员或读者，启用 / 禁用用户、重置密码并按来源 ID 授权。读者默认不获任何来源权限，新来源也不会自动授权。服务端对列表、搜索、详情、多版本、封面、页面、原文件、下载和事件统一检查权限。修改密码、禁用账号或改变授权会撤销现有会话。

App 的服务器设置包含来源、栏目、扫描刮削、元数据服务、缓存及账户安全，另设用户授权入口；与设备阅读偏好分别保存。设置使用修订号检查并发修改，密钥留空保留、明确勾选才清除，保存来源之后需另行启动扫描。

AI 服务使用 OpenAI 兼容的 Chat Completions 接口。在网页或 App 的“元数据服务”中填写 URL 和 API Key 后，会自动获取模型列表；选择模型后，再从下拉菜单选择思考程度。URL 可填写服务根地址、带 `/v1` 的地址或完整的 `/chat/completions` 地址。新安装默认地址为 `https://api.openai.com/v1`，模型需从实际列表选择；已有 DeepSeek 设置和密钥会兼容读取。更换服务地址时需重新输入密钥。

思考程度统一提供“无、低、中、高”四档，已知模型不支持的档位会禁用；未知模型提供这四个标准选项。可用“测试模型调用”验证当前组合（会发送简短请求，可能产生少量 API 费用）。

刮削默认同时处理 4 部作品，可在“扫描与刮削”调整为 1–8；全局 AI 请求并发默认 4，可在“元数据服务”调整为 1–12。普通、联网和连接测试共用 AI 请求上限，相邻实际发送至少间隔 3 秒；等待发送不占并发名额，相同的并发请求合并。

并发数在保存后立即参与调度：调高会补充排队任务，调低会等待在途任务结束，不中断请求。手动对一本或多本书重新刮削时，按提交顺序优先使用空出的名额，相关 AI 请求也优先；重复点击合并，同一本书不会同时刮削两份。

配置 AI 后，文件名和目录名由 AI 解析为标准结构并缓存；主作品、卷册的语义匹配与校验由 AI 决定，程序保留格式、候选 ID 和资源对应检查。整部刮削失败后，通过 AI 将当前已有元数据简体中文化，全部字段有效后才保存；中文化也失败时报告失败并保留现有记录。

强制重新刮削会重新解析原始名称、搜索候选、匹配主作品、抓取详情、中文化及匹配全部卷册，跳过已有 ID、名称缓存和共享元数据缓存；仅本次明确指定的 Bangumi ID 例外。网页版关联条目中，当前账号可访问的本地作品显示“本地可读”，支持跨栏目互相跳转，其他卡片继续打开 Bangumi。详见[元数据刮削流程](metadata-scraping.md)。

文件监听按变动路径处理新增、修改、删除和重命名：独立文件只处理该文件，系列目录只重扫所属系列，不再因新增一本遍历全部来源。文件写入稳定后约每 2 秒合并一批，保存索引后自动刷新书架。批量刮削会在当前作品完成后让局部扫描先执行，再继续剩余队列。首次导入和手动扫描仍校验全库；来源恢复连接时仅校验该来源，读取失败或来源离线时保留已保存的书库。

扫描始终使用本地名称解析和目录结构推断，不调用 AI。开启“AI 联网刮削”后，每个需要全量刮削的作品最多通过一次联网 AI 请求识别主作品 ID，再由程序读取 Bangumi 详情、人物、关联与卷册。直接使用 AI 返回的正整数 ID，不额外核验证据或条目；识别失败转入传统候选召回。书名优先采用 Bangumi 中文名，缺少时与人名、简介一样使用普通 AI 翻译，不再联网检索译名。

切换模式不会覆盖已有结果，包括部分结果和已保存的本地回退。新增或变化的卷册仅补充对应资源，旧主作品和已有详情保持不变。只有显式强制重刮才跳过缓存并完整替换，失败时保留旧结果；设备相同描述也跨模式复用。旧联网结构继续兼容展示，新结果采用共享传统详情结构。详见 [扫描与刮削说明](metadata-scraping.md)。

联网开关复用原设置字段，默认开启，保存后对之后启动的任务生效。作品匹配和卷册匹配在两种模式下均可使用。“测试联网搜索”独立核对实际搜索调用及 Bangumi 官方来源，用于验证服务能力。

作品封面默认优先采用已刮削的 BGM 封面，缺少时使用本地封面；手动上传或从页面选取的封面优先。已有 BGM 元数据无需重新刮削即可应用这一顺序，网页与 iOS 使用相同结果。

无需开启调试模式，默认 `[scrape]` 日志就会记录任务编号、作品名、原始目录或文件名，以及识别、详情读取、卷册匹配和保存等关键步骤。每次单本或批量任务结束后输出成功、失败、跳过数量，并逐行列出失败作品的原始路径和原因。主作品刮削失败后即使本地中文化回退成功，仍计入刮削失败；已有结果或禁用来源会说明跳过原因。成功数量按作品计算，卷册未匹配或可选步骤失败在对应步骤单独说明。

排查模型或联网测试失败时，可在网页或 iOS 的“服务器设置 → 元数据服务 → 调试与诊断”开启“调试模式”并保存，然后重新点击测试。默认关闭，保存后立即生效，旧客户端保存其他设置时保留该开关。详细日志以 `[debug]` 开头，输出到服务器标准输出；Docker Compose 部署可用 `docker compose logs -f --tail=200 readdeck` 查看。日志包含当前设置、设置操作、AI 请求地址/模型/参数/提示词、HTTP 状态和请求编号、Responses 流事件、模型响应、来源验证结果、耗时与错误堆栈；流事件随接收记录，逐 token 增量以计数和组装结果代替。页面错误中的请求编号对应日志的 `traceId`，每个上游调用另有 `requestId`。API Key、密码、Token、Cookie 和已知凭据会脱敏，单段文本最多保留 12000 字符、每条日志内容约 60000 字符，截断位置有标记。日志可能包含书名、提示词和模型回答，排查后请关闭；关闭后停止新增详细日志，包括尚未结束的请求，历史日志由部署环境保留。

“测试联网搜索”会拒绝只有普通回答或文本 `<tool_call>`、没有实际 `web_search_call` 的结果，即使接口返回 HTTP 200。错误页面现在保留 HTTP 状态和请求编号；若服务器或反向代理返回 HTML/空响应，会明确提示未返回有效 JSON，便于区分上游 AI 错误与部署故障。

本地新建栏目保存在设备上。刮削任务可后台继续，重启后恢复查询，失败时可在书籍菜单中重试。服务端优先复用已有作品和卷册元数据，并合并相同识别请求及同作品的并发处理；同名异作者及小说/漫画改编不会仅凭名称自动合并。详见[本地导入与元数据复用](local-import-metadata.md)。
